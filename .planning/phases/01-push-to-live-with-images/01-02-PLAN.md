## Phase Goal

**As a** portfolio owner, **I want to** write a project markdown file with a pasted image and push it to GitHub, **so that** I see it live on a deployed site with optimized images.

<objective>
This plan adds error states to the skeleton slice. Every content mistake the owner can make in a project or page file stops the build with a message that names the file and the field or link. Optional metadata renders as a `<dl>`, standalone pages get root URLs, and unknown URLs get a plain 404.

Purpose: PUB-04 and D-23. The owner should never deploy a silently broken page.
Output: lib/validate.js wired into the config, the pages directory data, 404.md, the layout metadata block, and a test per failure class.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Tampering | lib/validate.js slug → permalink | mitigate | Slug regex ^[a-z0-9-]+$ blocks `../` and `/`, which stops writes outside _site/<slug>/. The test "Bad slug format" proves it |
| T-01-05 | Tampering | reserved paths (img, assets, 404, tags) | mitigate | RESERVED_SLUGS check stops a project overwriting _site/img or the 404 page |
| T-01-06 | Denial of service | build | accept | Content is owner-authored. A failed build simply does not deploy |
| T-01-07 | Information disclosure | error messages | accept | Errors print only repo-relative paths in local or CI logs. There are no secrets |
</threat_model>
