## Phase Goal

**As a** portfolio owner, **I want to** write a project markdown file with a pasted image and push it to GitHub, **so that** I see it live on a deployed site with optimized images.

<objective>
Walking skeleton, local half. After this plan, the owner can write `content/projects/tidepool-game.md` with an image from `assets/` and run `npm start` (live reload) or `npm run build`. They then get a real project page at `/portfolio-test/tidepool-game/` with responsive WebP/JPEG `<picture>` output, CSS loaded through the base path, and no originals published. Changing one value (`PATH_PREFIX`) switches between subpath hosting and root hosting.

Purpose: this proves the riskiest pipeline first: asset resolution by basename, the image transform, base path, and front matter dates.
Output: the scaffold, the Eleventy config and `lib/` modules, the sample project, and an end-to-end test harness that later plans reuse.
</objective>

<interfaces>
Contracts created by this plan and consumed by plans 02, 03, 04, 05. Implement exactly these signatures.

lib/assets.js:
- buildIndex(fileNames: string[], dir: string): Map<string, string>. Pure. Key = lowercased basename, value = path.resolve(dir, name). Throws Error("assets/: case-only duplicate filenames: <a> and <b>") on a key clash.
- refreshAssets(dir = "assets"): Promise<void>. Reads the directory, ignores dotfiles (.gitkeep, .DS_Store) and calls buildIndex. It stores the module-level index. Plan 04 extends it to fill the alpha Set.
- resolveAsset(nameOrLink: string): string | null. Takes path.basename, then decodeURIComponent, then lowercases. It looks the result up. On a miss it synchronously re-scans the directory once (Pitfall 7) before returning null.
- getIndex(): Map<string, string>

lib/markdown.js:
- installAssetResolver(md): void. Pushes the core rule "asset_resolver".

lib/images.js:
- export const FORMATS = ["webp", "jpeg"]   (prepend "avif" to enable AVIF, per D-21)
- export const imageOptions = { formats: FORMATS, widths: [480, 960, 1600, 2400], urlPath: "/img/", outputDir: "_site/img/", failOnError: true, htmlOptions: { imgAttributes: { loading: "lazy", decoding: "async", sizes: "(min-width: 60em) 60em, 100vw" } } }

lib/frontmatter.js:
- parseFrontMatter(str: string): object. It runs js-yaml load after the date pre-quote regex from RESEARCH Pattern 5.
- readFrontMatter(filePath: string): object. Reads the file, extracts the leading YAML block between the "---" fences, and returns parseFrontMatter of it, or {} if there is none. Plan 02 uses it to check for unknown keys.

test/helpers/site.js:
- defaultPrefix(): string. It reads the repo eleventy.config.js and returns the capture of /PATH_PREFIX \?\? "([^"]+)"/. Tests use it instead of hard-coding "/portfolio-test/", so plan 05 can change the default without touching any test.
- makeSite({ files = {}, assets = {}, prefix, useRepoContent = false }): Promise<{ dir, build(env?): { code, stdout, stderr }, read(relPath): string, exists(relPath): boolean, cleanup() }>
  - It creates a temp dir (fs.mkdtempSync under os.tmpdir()). It copies eleventy.config.js, lib/, src/ and package.json from the repo root, and symlinks node_modules.
  - With useRepoContent it copies content/ and assets/. Otherwise it writes only the given `files` (path -> string) and creates an empty assets/ dir.
  - `assets` maps a filename to either a Buffer or a spec { width, height, alpha?: boolean, format: "webp"|"png"|"jpeg"|"gif"|"svg", animated?: boolean }, which is generated with sharp.
  - build() runs node_modules/.bin/eleventy with cwd = dir, env PATH_PREFIX = prefix (when given), and spawnSync. It never passes --output, because imageOptions.outputDir is fixed at _site/img/.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → repo | Third-party build dependencies are installed |
| content/*.md → build | Author-controlled links are resolved to filesystem paths |
| build output → public site | Anything in _site/ becomes public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | npm installs (eleventy, eleventy-img, sharp, js-yaml) | mitigate | Task 1 blocking human check on npmjs.com before the install. package-lock.json is committed, and CI uses `npm ci` (plan 05) |
| T-01-01 | Tampering / Information disclosure | lib/markdown.js resolver | mitigate | Only the basename is used. The lookup goes through the assets/ index Map, so `../../../etc/x` cannot reach files outside assets/. A miss throws |
| T-01-02 | Information disclosure | eleventy.config.js passthrough | mitigate | assets/ is never passthrough-copied. The "originals not published" test asserts that no assets/ basename appears in _site |
| T-01-03 | Information disclosure | image derivatives metadata | accept | eleventy-img/sharp drop metadata from derivatives by default. Commit-time stripping (D-16) is in plan 03 |
</threat_model>
