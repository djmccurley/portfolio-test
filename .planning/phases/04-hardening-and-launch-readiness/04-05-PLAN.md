    1. Create scripts/check-reflow.mjs (ESM, `node:` built-ins only, no new dependency). Usage: `node scripts/check-reflow.mjs [siteDir]`, where siteDir defaults to `_site`.
       - Chrome binary: `CHROME_BIN`, then `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, `/usr/bin/google-chrome`, `/usr/bin/chromium`, `/usr/bin/chromium-browser`, using the first that exists. If none exists, print `check-reflow: Chrome not found. Set CHROME_BIN to a Chrome or Chromium binary.` to stderr and exit 2.
       - If `<siteDir>/index.html` is missing, print `check-reflow: <siteDir>/index.html not found. Run npm run build first.` and exit 2.
       - Prefix: `process.env.PATH_PREFIX`, else the default parsed from eleventy.config.js with the same regex as `defaultPrefix()`. Normalise it to start and end with `/`.
       - Start a `node:http` server on host `127.0.0.1`, port 0:
         - `GET /__measure?w=<w>&p=<p>`: `w` must be an integer from 200 to 2000 and `p` must start with the prefix or `/__reflow/`, otherwise respond 400. The response is a wrapper page with an `<iframe>` of width `w`px, height 800px and no border (src = `p`, HTML-escaped), a `<pre id="out">pending</pre>`, and an inline script. On iframe load, the script waits 500ms, then reads the iframe document's `documentElement.scrollWidth` and `clientWidth`. It collects offenders: elements in the iframe body whose `scrollWidth > clientWidth + 1` and `clientWidth > 0`, reported as lowercase tag name plus first class. It writes `RESULT scrollWidth=<n> clientWidth=<n> offenders=<comma list>` into `#out`. Measure per-element `scrollWidth`, not bounding rects, because overflowing text does not change its box rect (RESEARCH Pattern 7).
         - `GET /__reflow/stress/`: the stress page. `GET /__reflow/canary/`: the canary page.
         - `GET <prefix><rest>`: decode the path, resolve it under siteDir, and respond 404 to anything that resolves outside siteDir. A directory serves its `index.html`. Set content types for html, css, js, webp, jpeg/jpg, png, gif, svg, avif, mp4, webm, pdf, xml and txt. Everything else is 404.
       - Pages to measure: every `index.html` under siteDir, skipping the `img/`, `video/` and `pdf/` dirs, mapped to `<prefix><dir>/` (the root maps to the prefix), plus `<prefix>404.html` when present, sorted.

         - a `pre` with an unbroken 200-character token
         - a meta `dl` with `dt` Role/`dd` Design and `dt` Link/`dd` holding an `<a>` whose text is a 200-character URL
         - a raw `<table>` with 6 header cells and 1 row of 6 long tokens
         - a `<ul class="filters">` of 8 links
         - a `<nav class="pager" aria-label="Projects">` whose two links have 60-character single-word titles
       - Canary page: the same stylesheet and a `<main>` with `<div style="width: 2000px">canary</div>`.
       - Widths: 320 and 640.
       - For each page and width, run Chrome with Node's async `execFile`, promisified. Do not use any synchronous spawn: the HTTP server runs in this same process and must keep answering. Pass the argument array `--headless=new`, `--disable-gpu`, `--no-first-run`, `--no-default-browser-check`, `--user-data-dir=<mkdtemp dir>`, `--virtual-time-budget=5000`, `--dump-dom`, then the wrapper URL, with a 60s timeout and no shell. Parse `RESULT scrollWidth=(\d+) clientWidth=(\d+) offenders=(.*)`. A missing RESULT counts as a failure, `no RESULT`.
       - Print `ok   <w> <path>` or `FAIL <w> <path> scrollWidth=<n> clientWidth=<n> offenders=<list>` for site pages and the stress page. The canary passes only when it overflows at both widths; otherwise print `FAIL canary did not overflow: the check is not measuring`.
       - Exit 0 only when every site page and the stress page are clean at both widths and the canary overflowed, ending with `check-reflow: <N> pages x 2 widths, no horizontal overflow`. Otherwise exit 1. Always close the server and remove the temp profile dir.
    2. package.json: add `"check:reflow": "node scripts/check-reflow.mjs"` to scripts. Leave `build`, `start` and `test` byte-identical. plan 04-01's workflow test pins `build` and `start`. This check is local only and is not added to `npm test` or CI, because it needs a browser (RESEARCH Pattern 7).

Expect exit 1 with FAIL lines for the stress page (at least `blockquote`/`pre`/`table` cells at 320 and the `dd` link at 640). Record the FAIL lines in the SUMMARY. If the stress page passes before the fix, the stress content is too weak: lengthen it until it fails.

       - Directly after that rule, add `pre, td, th { overflow-wrap: anywhere; }` with a one-line comment: `anywhere` also lowers min-content, so table columns and preformatted tokens shrink to fit, which `break-word` does not.
       - In the `@media (min-width: 40em)` block, change the `dl` columns to `auto minmax(0, 1fr)` and give `dd` `min-width: 0` alongside its `margin: 0`.
       - Do not use `overflow: hidden`, fixed widths, new font sizes or weights, or `display` changes on `table` (keeps table semantics for screen readers).

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
