## Phase Goal

**As a** portfolio owner, **I want to** compose a rich project page by typing short block shorthand that mixes grids, full-width images, text, video and playable games, **so that** it renders as an accessible brutalist page.

<objective>
This plan delivers the block syntax engine. The owner types `::: grid-2/3/4` and `::: full` fences around pasted `![alt](path "Caption")` lines, mixes them with ordinary text and raw HTML, and gets semantic `<figure>`/`<figcaption>` markup with the right responsive `sizes` per block. Every malformed block fails the build naming the file and line.

Purpose: BLOCK-01..05 and AUTH-04 are the core of the phase goal; D-01..D-05 lock the syntax. Plans 02-03 (alt lint) and 02-04 (embeds) build on the `installBlocks` hooks created here. The CSS that lays these blocks out lives in plan 02-02 and targets the same UI-SPEC markup contract.
Output: lib/blocks.js, lib/locate.js, updated lib/markdown.js, lib/images.js and eleventy.config.js, two new test files, two new devDependencies.
</objective>

Existing code (Phase 1, read before changing):

- lib/markdown.js: `export function installAssetResolver(md)` pushes core rule "asset_resolver". For every image token in `block.children` it skips remote and data: sources, resolves the src with `resolveAsset(src)` (throws `${page.inputPath}: image not found in assets/: ${src}` when missing), rewrites src to a path relative to the page, sets "eleventy:formats" ("svg", "webp,gif", or "webp,png" via hasAlpha), and sets `loading="eager"` + `fetchpriority="high"` on the first image only.
- lib/assets.js: `resolveAsset(nameOrLink) -> absolutePath | null` (basename lookup, sync re-scan on a miss), `hasAlpha(basenameLower)`, `refreshAssets(dir)`.
- lib/images.js: `imageOptions.htmlOptions.imgAttributes = { loading: "lazy", decoding: "async", sizes: "(min-width: 60em) 60em, 100vw" }`; widths [480, 960, 1600, 2400].
- eleventy.config.js: `eleventyConfig.amendLibrary("md", (md) => installAssetResolver(md));` and `markdownTemplateEngine: "njk"` (Nunjucks runs over markdown first, so `{#` starts a Nunjucks comment).
- test/helpers/site.js: `makeSite({ files, assets, prefix, useRepoContent })` returns `{ dir, build(env) -> { code, output }, read(rel), exists(rel), walk(rel), cleanup() }`. - markdown-it-container 4.0.0 (read from its source in research): the open token is `container_block_open` with `token.info = params` (text after the colons, untrimmed) and `token.map = [startLine, nextLine]`; when the closer is found, `nextLine` is the closer line index, otherwise the block silently runs to the end of its parent. The container may interrupt a paragraph, list or blockquote.
- markdown-it-attrs 5.0.1 is CommonJS (`module.exports`), registers its rule with `md.core.ruler.before("linkify", ...)`, so it always runs before rules pushed with `md.core.ruler.push`. A bare `{decorative}` yields attribute `decorative=""`.
- markdown-it 14.3.3 (bundled by Eleventy; importable in tests as `import MarkdownIt from "markdown-it"`): image tokens hold `attrs` src/alt(empty)/title, the real alt text in `token.content` and parsed alt in `token.children`; the default image rule fills alt at render time. `renderToken` returns "" for tokens with `hidden = true`.

Created here (contracts other plans consume):

- lib/locate.js: `export function locator(state)` returns `{ file, lineOf(token), fail(token, message) }`. `file` is `state.env?.page?.inputPath ?? "markdown"`. The line offset is computed once per call: raw file lines (read `file` with fs.readFileSync, normalise CRLF to LF) minus `state.src.split("\n").length`; 0 when the file cannot be read. `lineOf(token)` is `token.map[0] + 1 + offset`, or "?" when the token has no map. `fail` throws `new Error(`${file}:${lineOf(token)}: ${message}`)`.
