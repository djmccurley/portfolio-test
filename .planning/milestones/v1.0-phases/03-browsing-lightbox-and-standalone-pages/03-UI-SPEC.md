# Phase 03 — UI Design Contract

> Visual and interaction contract for Phase 03: Browsing, Lightbox and Standalone Pages. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Same system as Phase 02: a static Eleventy site, one hand-written `content/style.css` driven by CSS custom properties, no component library, no Tailwind, no `components.json`. This phase adds new surfaces (header nav, card grid, tag filter row, lightbox dialog, standalone pages) and **reuses every Phase 02 token**. No new colour, no new font size, no new weight, no new spacing step.

Sources: decisions D-01..D-17 from `03-CONTEXT.md` (locked); `02-UI-SPEC.md` (approved tokens, type scale, layout column, focus and motion rules); `02-UI-REVIEW.md` (carry-over warnings); `content/style.css`, `src/_includes/base.njk`, `lib/images.js`, `test/design.test.js` (current code). Items marked "(default)" are researcher recommendations inside Claude's Discretion; the owner can tune them in one place.

### Browser support decisions for the lightbox (research flag from CONTEXT)

Checked 2026-10-30.

- `<dialog>` with `showModal()`, `close()` and the `close` event is Baseline widely available (Chrome 37, Firefox 98, Safari 15.4). Use it with no polyfill. If `typeof HTMLDialogElement !== "function"` the script does nothing and the plain links keep working.
- Invoker commands (`command="show-modal"` plus `commandfor`) are Baseline 2025 "newly available", but they exist only on `<button>`, never on `<a>`. The trigger here must stay a real link so it works without JS, so **do not use invoker commands**. Use a delegated click handler and `showModal()`.
- `closedby="any"` (light dismiss) is not in Safari. **Do not rely on it.** Backdrop click is handled by the script (see Lightbox Contract).

Source: [MDN Invoker Commands API](https://developer.mozilla.org/docs/Web/API/Invoker_Commands_API), [InfoQ on HTML invoker commands](https://www.infoq.com/news/2026/01/html-invoker-commands).

## Layout Contract

### Page column (unchanged)

Phase 02's named-line grid, `--page-margin`, `--column-max` (80rem) and `--measure` (40rem) apply to every new page. Everything is left-aligned. Only prose is capped at `--measure`. Card grids, filter rows and the header use the full `content` column.

Two traps in the existing CSS the planner must handle:

1. The prose-cap selector `main > :is(p:not(.lone-image), h1, h2, h3, ul, ol, dl, blockquote, pre)` matches a bare `<ul>`. `ul.cards` is a direct child of `<main>` and must be **excluded** (`ul:not(.cards)`), or the card grid collapses to 40rem. The filter row is a `<nav>`, so it is not matched.
2. `02-UI-REVIEW.md` fix 1 (rhythm rules losing on specificity) may still be open. Add `.cards` to the block-rhythm selector list **and** make sure the heading-below rule (16px) still beats it. Verify the gaps in the Vertical rhythm table below with a built-page test, not by reading the CSS.

### Card grid (D-06, D-07)

One partial, `src/_includes/card.njk`, used by `/work/`, `/tags/<slug>/` and the homepage. Featured cards are identical to feed cards (D-07).

```html
<ul class="cards">
  <li>
    <a class="card" href="/tidepool-game/">
      <!-- cover: <picture><img src alt="{cover_alt}" width height sizes ...></picture> -->
      <span class="card-title">Tidepool</span>
      <time class="card-date" datetime="2024">2024</time>
    </a>
  </li>
</ul>
```

Rules:
- The whole card is **one `<a>`** (D-06). Cover, title and date are all inside it. Tags never appear on cards.
- The cover keeps `cover_alt` as its `alt` (Phase 01 requires it). The link's accessible name is therefore "alt, title, date". That is verbose but complete and needs no extra markup (default; the planner may leave it).
- Not a heading: cards are `<li>` in a `<ul>`, so the page keeps one `<h1>` plus, on the homepage only, one `<h2>`. Screen reader users get "list, N items".
- The date is printed **exactly as written** in front matter (Phase 01 D-07): `datetime` and visible text are the same string. No reformatting.
- **Covers are cropped to one aspect ratio** (owner decision, 2026-10-30). Every cover shows at **4:3** (`aspect-ratio: 4 / 3; object-fit: cover; object-position: center`), so each row of cards has an even height and titles line up. The ratio is one CSS value on `.cards img`; changing it re-crops every card with no rebuild of images. The crop is CSS only: the pipeline still publishes the full image, and `cover_alt` still describes the whole image.
  - This is the **only** place in the site where cropping is allowed. Grids, lone images, `::: full` and the lightbox stay uncropped. Narrow `test/design.test.js` so `object-fit` and `aspect-ratio` on `img` are allowed only in rules whose selector starts with `.cards`, and stay forbidden everywhere else. `overflow: hidden` stays forbidden everywhere.
  - Because cropping is centred, a subject near the edge of a cover may be cut off. The owner picks or prepares covers with that in mind. A per-project crop position (for example a `cover_position` front matter field) is out of scope for this phase.
- A card has a cover, a title and a date, all required by Phase 01 validation, so there is no "partial card".

```css
.cards { list-style: none; margin: 0; padding: 0; display: grid;
         grid-template-columns: repeat(3, minmax(0, 1fr));
         gap: var(--block-gap) var(--grid-gap); align-items: start; }
.cards img { display: block; width: 100%; height: auto;
             aspect-ratio: 4 / 3; object-fit: cover; object-position: center; }   /* the one allowed crop */
a.card { display: block; color: inherit; text-decoration: none; }
.card-title { display: block; margin-top: 0.5rem; font-weight: 700; color: var(--accent);
              text-decoration: underline; text-decoration-thickness: 0.08em; text-underline-offset: 0.2em; }
.card-date { display: block; color: var(--ink); text-decoration: none; }   /* 14px Label via the existing `time` rule */
```

`a.card:visited` must not change colour: the title and date set their own explicit colours, so the global `a:visited` accent does not leak into the date.

Collapse (pure CSS, em media queries, literals; identical breakpoints to `grid-3`):

| `>= 60em` (960px) | `40em - 59.99em` | `< 40em` |
|-------------------|------------------|----------|
| 3 columns | 2 columns | 1 column |

```css
@media (max-width: 59.99em) { .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
@media (max-width: 39.99em) { .cards { grid-template-columns: minmax(0, 1fr); } }
```

Card cover images (default):
- Pipeline unchanged: widths `[480, 960, 1600, 2400]`, webp + jpeg.
- `sizes` (same as `grid-3`): `(min-width: 90em) 416px, (min-width: 60em) 30vw, (min-width: 40em) 45vw, 90vw`.
- Loading: the first card cover on a page is `loading="eager"` and `fetchpriority="high"`; every other cover is `loading="lazy"`. This keeps Phase 01's "first image on the page is eager" rule, because the header contains no image.

## Lightbox Contract (IMG-05, D-01..D-04)

### Which images get a zoom link

| Image context | Zoom link? |
|---------------|-----------|
| Lone image in the column, with or without caption | yes |
| Image in `::: grid-2`, `grid-3`, `grid-4` | yes |
| Image in `::: full` | **no** (D-01) |
| Card cover | no (links to the project) |
| Video poster | no |
| Decorative image (`{decorative}`, `alt=""`) | **no** (default; a link with no text alternative has no accessible name, a WCAG failure) |
| Raw HTML `<img>` the owner wrote by hand | no (raw HTML passes through untouched, AUTH-04) |
| Image with empty alt that is not marked decorative | yes (already warned by the alt lint); the hidden suffix below keeps the link nameable |

D-01 says "every content image"; a decorative image is not content, so excluding it is consistent.

### Zoom link markup

```html
<a class="zoom" href="/img/abc123-2400.webp" data-width="2400" data-height="1500">
  <picture>...thumbnail srcset, alt="The alt text"...</picture>
  <span class="visually-hidden"> (full size)</span>
</a>
```

- `href` is the largest published variant: the 2400px webp, or the image's own size when smaller (D-02). Animated GIFs link to the published GIF itself so the animation survives (default). SVG links to its published file. Originals in `assets/` are never linked (IMG-03).
- `data-width` and `data-height` are the intrinsic size of the linked file, used by the script to reserve space.
- Link text is the image `alt` plus the hidden suffix ` (full size)`, so the accessible name is "{alt} (full size)".
- The caption stays outside the link: `<figure><a class="zoom">...</a><figcaption>...</figcaption></figure>`. Lone untitled images become `<p class="lone-image"><a class="zoom">...</a></p>`.
- Styling: `a.zoom { display: block; cursor: zoom-in; text-decoration: none; }`. It shows the normal 3px accent focus ring with 3px offset (existing `a:focus-visible`). No hover change (A11Y-01).

### Dialog

One shared `<dialog class="lightbox">`, created by the script on first open and reused. A page with no JS has no dialog markup at all. Load the script only on pages that contain a `.zoom` link (default; for example `{% if '<a class="zoom"' in content %}`), via a base-path-safe URL: `<script src="{{ '/lightbox.js' | url }}" defer></script>`. Add `content/lightbox.js` to the passthrough copy.

```html
<dialog class="lightbox" aria-label="Full-size image">
  <button type="button" class="lightbox-close">Close</button>
  <figure>
    <img src="" alt="">
    <figcaption hidden></figcaption>
  </figure>
</dialog>
```

Behaviour (all required, tests can assert each):

| Event | Behaviour |
|-------|-----------|
| Plain left click on `a.zoom` | `preventDefault()`, fill the dialog, `showModal()`. |
| Click with Ctrl/Cmd/Shift/Alt, middle click, or `target` links | Script does not intercept; the browser opens the large file normally. |
| Fill | `img.src = link.href`; `img.alt` = the thumbnail's `alt` (identical); `img.width/height` from `data-width/data-height`; caption text = the figure's `figcaption` text, otherwise `figcaption.hidden = true`. Alt and caption are never merged. |
| Focus on open | Native `showModal()` focus goes to the first focusable element, the Close button, because it is first in the DOM. Focus is trapped by the modal dialog (page behind is inert). |
| Escape | Closes (native `cancel` then `close`). |
| Close button | `dialog.close()`. |
| Backdrop click | `dialog.addEventListener("click", e => { if (e.target === dialog) dialog.close(); })`. The dialog fills the viewport, so "backdrop" means any click on the dialog's own surface outside the image, caption and button. A click on the image or caption does nothing. |
| On `close` | `opener.focus()` explicitly (do not rely on the browser), then clear `img.src` so the next open does not flash the previous image. |
| Large image fails to load (`error` event) | Close the dialog and navigate to `link.href`, i.e. fall back to the plain-link behaviour. No error copy. |
| Script fails or is blocked | Nothing is broken: the link opens the large file in the tab; the Back button returns to the page. |

No animation, no transition, no fade, no zoom effect (A11Y-01). The script contains no `requestAnimationFrame`, no timers.

### Dialog visual (default; within Phase 02 tokens)

The dialog is an **opaque, full-viewport, ink surface**: white (`--paper`) text on black (`--ink`), contrast 21:1. It is deliberately not translucent, so there is no backdrop-contrast question and "click the backdrop" is simply "click empty space".

```css
dialog.lightbox {
  position: fixed; inset: 0; width: 100%; height: 100%; max-width: none; max-height: none;
  margin: 0; border: 0; padding: var(--grid-gap) var(--page-margin);
  background: var(--ink); color: var(--paper);
  overflow: auto; overscroll-behavior: contain;
}
dialog.lightbox::backdrop { background: var(--ink); }
dialog.lightbox[open] { display: grid; justify-items: center; align-content: start; gap: var(--grid-gap); }
.lightbox-close { justify-self: end; }
.lightbox figure { margin: 0; width: fit-content; max-width: 100%; }
.lightbox img { display: block; width: auto; height: auto;
                max-width: 100%; max-height: calc(100dvh - 10rem); }   /* fits the viewport, never cropped, never upscaled */
.lightbox figcaption { margin-top: 0.5rem; text-align: left; }        /* Label: 14px italic, inherited from the global figcaption rule */
```

- `display: grid` must be set on `dialog[open]` only, never on `dialog`, or the closed dialog would show.
- The viewer centres the image (the one deliberate exception to the left-aligned site; a viewer reads as a stage). Caption text stays left-aligned under the image's left edge.
- Images smaller than the viewport show at their own size (no upscaling blur). A very tall image shrinks via `max-height`; a long caption makes the dialog scroll (`overflow: auto`), the page behind does not.
- `object-fit` (allowed only on `.cards img`) and `overflow: hidden` are not used in the lightbox. Do not lock page scroll with `overflow: hidden`; the modal's `overscroll-behavior: contain` is enough.
- **Close button** (default): Body size 18px, weight 700, `background: var(--paper); color: var(--ink); border: 2px solid var(--paper); border-radius: 0; padding: 0.75rem 1rem;` (about 51px tall, same padding as the skip link). No icon, no "×" glyph; the visible text is the label.
- **Focus ring inside the dialog is white.** The global ring is `--accent` (#0000ee), which is about 2.2:1 on black and fails the 3:1 focus requirement (the same weakness `02-UI-REVIEW.md` found on the skip link). Add `dialog.lightbox :focus-visible { outline-color: var(--paper); }` and extend `test/contrast.test.js` with a ring-versus-surface check (`--paper` on `--ink`, at least 3:1). Keep `outline: 3px solid`, `outline-offset: 3px` from the global rule; the existing regex test on the global `:focus-visible` rule still passes.

## Standalone pages: PDF links (D-15..D-17)

| Item | Contract |

## Interaction & Accessibility Contract

| Concern | Contract |
|---------|----------|
| Motion (A11Y-01) | None. No dialog animation, no `::backdrop` transition, no hover or card effects, no smooth scroll. The Phase 02 reduced-motion guard stays. |
| Current page in nav | `aria-current="page"` on the nav link whose URL equals the current page. `aria-current="true"` on **Work** while on a tag page or a project page (the current section; D-14). **CV** and **Teaching** are `page` only on their own pages. The owner-name link has `aria-current="page"` on the homepage. Visual treatment: the current item is `color: var(--ink); font-weight: 700` and stays underlined, so it is distinguished by weight and colour, not colour alone. Style via `[aria-current]`, not a separate class. |
| Filter row current | `aria-current="page"` on `All` at `/work/` and on the tag's link at `/tags/<slug>/`. Same style as above. |
| Landmarks | `<header>` contains `<nav aria-label="Main">`; the filter row is a second `<nav aria-label="Filter work by tag">`; `<main id="main">` unchanged. Skip link stays the first focusable element and still targets `#main`. |
| Headings | One `<h1>` per page. Homepage adds one `<h2>`. CV and Teaching use `##` and do not skip levels. Cards are not headings. |
| Keyboard | All nav, filter, card and zoom links are Tab-reachable in DOM order: header, then content. Enter activates a link. In the lightbox: Tab cycles inside (only Close is focusable), Enter or Space on Close closes, Escape closes. After close, focus is on the link that opened it. |
| Focus visibility | Global 3px accent ring everywhere; white ring in the lightbox. `a.card` shows the ring around the whole card. Never `outline: none` except the existing `main` skip-target rule. |
| Dialog semantics | Native modal `<dialog>` (focus trapped, page inert, Escape built in). `aria-label="Full-size image"`. The image has the same `alt` as the thumbnail. Closing returns focus to the opener. |
| Target size | Links have at least 35px tall hit areas (WCAG 2.2 AA minimum 24px). Close button about 51px. |
| Images | Every `<img>` keeps its `alt`. Card covers use `cover_alt`. Zoom links add the hidden suffix. |
| Zoom / reflow | All new sizes in `rem`, `em`, `%`, `fr`, `dvh`. `min-width: 0` on card and dialog children. Formal 320px and 200% zoom verification is Phase 04 (A11Y-02), but the header, filter row and cards must wrap rather than scroll. |
| Base path | Every new URL (nav, cards, filter links, tag links, PDFs, large-image targets, `lightbox.js`) goes through the base-path helper and works under `/portfolio-test/` and at `/`. |
