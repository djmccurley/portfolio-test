<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → Pages | The CI identity publishes the public site |
| actions/cache → build output | A restored cache becomes part of the published artifact |
| third-party actions | Code from the actions/* org runs in CI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-15 | Elevation of privilege | deploy.yml permissions | mitigate | Top-level permissions are exactly contents: read, pages: write, id-token: write. There are no secrets and no pull_request_target. test/workflow.test.js asserts this |
| T-01-16 | Tampering | third-party actions | mitigate | Only first-party actions/* majors are used. `npm ci` installs from the committed lockfile. SHA pinning is accepted as optional for a personal site |
| T-01-17 | Information disclosure | stale cached derivatives published | mitigate | prune-img removes every _site/img file that no built HTML references before upload, and the `du -sh _site` line exposes size drift |
| T-01-18 | Information disclosure | public repo exposes .planning/ and assets/ | accept | The owner approves the public repo in Task 2. assets/ holds only shrunk, metadata-stripped WebP, which check-assets enforces |
| T-01-19 | Tampering | cache poisoning | accept | Cache entries are written only by this repo's own main-branch runs. Workflows from forked PRs do not run (push to main only) |
</threat_model>
