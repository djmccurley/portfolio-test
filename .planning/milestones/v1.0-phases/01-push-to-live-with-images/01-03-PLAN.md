## Phase Goal

**As a** portfolio owner, **I want to** write a project markdown file with a pasted image and push it to GitHub, **so that** I see it live on a deployed site with optimized images.

<objective>
This plan adds the commit slice. The owner pastes a full-size screenshot and commits as usual. The pre-commit hook scales the image to at most 3000px, converts it to WebP, slugifies the name, deletes the original and rewrites every `.md` link, all inside the same commit. A CI guard script catches anything that slipped past (`--no-verify` or another machine).

Purpose: AUTH-03 and D-13..D-19. Full-size files must never reach git history.
Output: scripts/shrink.js, scripts/check-assets.js, .githooks/pre-commit, package.json scripts and tests.
</objective>

Created here, scripts/shrink.js (ESM; it runs main() only when invoked directly, checked by comparing import.meta.url with process.argv[1]):
- export function slugifyName(fileName: string, outExt?: string): string. It uses path.parse and lowercases the stem. Runs of characters other than [a-z0-9] become "-", and leading and trailing "-" are trimmed. It appends outExt, or the lowercased original ext. Example: "Screenshot 2026-10-28 at 10.15.32.png" with ".webp" gives "screenshot-2026-10-28-at-10-15-32.webp", and "Another One.PNG" with ".webp" gives "another-one.webp". If the stem is empty after slugifying (for example "スクリーンショット.png" or "!!!.png"), it falls back to "image", giving "image.webp". planConversions then adds the usual -1, -2 collision suffix.
- export function planConversions(fileNames: string[], existing: Set<string>): Array<{ from, to, action: "webp-lossless"|"webp-lossy"|"heic"|"rename"|"none" }>. It assigns -1, -2... suffixes when `to` collides with an existing file or with another planned output.
- export function rewriteLinks(text: string, from: string, to: string): string. It replaces the raw from, encodeURI(from) and encodeURIComponent(from) forms, but only where the preceding char is one of ( / " ' or whitespace, and the following char is one of ) " ' ? # or whitespace, so "image.png" never matches inside "tidepool-game-image.png".

scripts/check-assets.js:
- export async function checkAssets(dir = "assets"): Promise<string[]> (error messages). Running it as a CLI prints them and exits 1 if there are any.

    - In manual mode, rewrite working-tree files only.
    - In --staged mode, also rewrite the INDEX copy of each tracked or staged .md. Read `git show :<path>`, apply rewriteLinks, write it with `git hash-object -w --stdin`, and set it with `git update-index --cacheinfo <mode>,<sha>,<path>`, keeping the mode from `git ls-files -s`. This avoids `git add` on .md files, so unstaged hunks are never swept in (Pitfall 6). It still keeps HEAD consistent even when the .md itself was not staged.

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Information disclosure | scripts/shrink.js | mitigate | sharp output without withMetadata strips EXIF/GPS (D-16). The test asserts that no exif is present. check-assets blocks raw JPEG/PNG in CI, so unstripped files cannot be deployed |
| T-01-09 | Tampering (command injection) | scripts/shrink.js git/sips calls | mitigate | execFileSync with argument arrays only, plus `--` before paths. The grep gate forbids execSync |
| T-01-10 | Denial of service (data loss) | shrink.js file replace | mitigate | Output goes to a temp file, then a rename. The original is deleted only after the rename succeeds. Any sharp error aborts the commit with exit 1 |
| T-01-11 | Tampering (commit integrity) | index rewrite | mitigate | Index blobs are rewritten through hash-object/update-index, so unrelated unstaged hunks never enter the commit (test "no sweeping") |
| T-01-12 | Denial of service | huge inputs (decompression bomb) | accept | The input is owner-supplied on their own machine. check-assets checks size before decoding |
</threat_model>
